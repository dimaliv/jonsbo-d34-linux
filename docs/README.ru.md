# Jonsbo D34 · Linux

[English](../README.md)

Фоновый сервис для передней панели Jonsbo D34. Передаёт местное время,
температуры CPU/GPU и текущую частоту CPU напрямую через USB HID.
Работает на стандартном Python без сторонних библиотек и без root.

## Проверенный сетап

- **ОС:** SteamOS 3.8.16, ядро Linux 6.16.12 Valve Neptune, Python 3.13.5.
- **CPU:** AMD Ryzen 7 9800X3D, датчик `k10temp/Tctl`.
- **GPU:** AMD Radeon RX 9070 XT 16 GiB, драйвер `amdgpu`, температура `edge`.
- **Плата:** ASRock B850M Steel Legend WiFi.
- **Корпус:** Jonsbo D34, USB `5131:2007`.

Встроенная Radeon тоже присутствует, но выбирается карта с наибольшим объёмом
VRAM. Поддержка Intel CPU и NVIDIA GPU пока не реализована. Другие устройства
с таким же USB ID не считаются автоматически совместимыми.

## Установка

Нужны Linux, Python 3.10+, поддерживаемые датчики и доступ к HID панели.
Для автозапуска нужна пользовательская сессия systemd. Из каталога проекта:

```sh
python3 src/panel.py --diagnose
python3 src/scripts/install.py install
```

Запускайте без `sudo`, системным Python. Установщик копирует программу в
`~/.local/share/jonsbo-d34`, создаёт пользовательский сервис и включает автозапуск.
Папка исходников после этого не нужна для работы сервиса. Существующие настройки
сохраняются. Поддерживаются `XDG_CONFIG_HOME` и `XDG_DATA_HOME`.

Сервис стартует при входе в пользовательскую сессию, включая игровой режим
SteamOS. Работа до входа пользователя не гарантируется.

## Интервалы

В `~/.config/jonsbo-d34.conf`:

```ini
UPDATE_INTERVAL=0.2
CPU_FREQ_INTERVAL=1
```

Пакеты отправляются каждые **200 мс**: при отправке раз в секунду на проверенной
панели наблюдалось мигание. Частота CPU считывается **раз в секунду**,
между измерениями передаётся сохранённое значение. Это не усреднение по времени:
каждое измерение — среднее текущих `cpu MHz` всех логических процессоров.
Остальные датчики и время обновляются при каждой отправке.

Для более редкой смены частоты поставьте `CPU_FREQ_INTERVAL=2` или `3`.
Оба интервала задаются положительными числами в секундах.

```sh
systemctl --user restart jonsbo-d34.service
systemctl --user status jonsbo-d34.service
journalctl --user -u jonsbo-d34.service -n 30 --no-pager
```

При отключении USB или временной потере доступа сервис повторяет подключение
через 3 секунды. После ошибки датчики обнаруживаются заново.

## Обновление и удаление

После обновления исходников повторите `python3 src/scripts/install.py install`:
настройки сохранятся, сервис будет перезапущен.

```sh
python3 src/scripts/install.py uninstall --dry-run
python3 src/scripts/install.py uninstall
```

Удаление останавливает сервис и убирает установленную программу, но сохраняет
конфигурацию. Остановка не отправляет команду очистки экрана.
Необязательное правило udev, установленное вручную, также сохраняется.

## Откуда протокол

Формат USB-пакета и карта числовых полей взяты из
**[coldwelderx/cooler-lcd-linux](https://github.com/coldwelderx/cooler-lcd-linux)**,
из файла [PROTOCOL.md](https://github.com/coldwelderx/cooler-lcd-linux/blob/bb2ef86f71da423c0b160fdcb941f3a563b907fe/PROTOCOL.md).
Автор исходного проекта исследовал Windows-приложение PC Monitor All.
В этом проекте протокол не исследовался с нуля; HID-дескриптор и отправка
пакетов проверены на указанном D34.

Здесь реализованы работа через Linux hidraw без зависимостей, чтение датчиков
Ryzen/Radeon, раздельные интервалы, переподключение и установка сервиса.

## Диагностика и ограничения

`python3 src/panel.py --diagnose` читает датчики без USB-записи.
`--once` отправляет один пакет (сначала остановите сервис).
Для ручного запуска: `python3 src/panel.py --interval 0.2 --cpu-freq-interval 1`.

При ошибке обязательного датчика отправка приостанавливается; панель может
оставить старое значение или погаснуть. Дополнительные недоступные поля
передаются нулевыми. Обращения к датчикам и USB влияют на точный период отправки.
Подробнее: [устранение неполадок](troubleshooting.md), [протокол](protocol.md).
